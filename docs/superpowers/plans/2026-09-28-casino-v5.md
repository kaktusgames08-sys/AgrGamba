# Casino v5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Upgrade the existing wheel's casino presentation, run continuity and stream controls.
**Architecture:** Keep the SVG wheel and tested RNG. Introduce a DOM-independent session model with versioned local storage, then connect a studio panel and a single responsive theme. Resolve and persist each selected outcome before its visual reveal.
**Tech Stack:** Vanilla JS, SVG, Canvas, Web Audio, Vite, node:test.
**Spec:** docs/superpowers/specs/2026-09-28-casino-v5.md

## Global Constraints
- Czech UI; preserve normal/Hardcore odds and amounts.
- No presentation change resets an active series.
- Whole run persists; archive insertion is idempotent by run ID.
- User initiates spins. Imported data is validated before mutation.
- CC0 audio files bundled locally, source/license documented.
- Mobile/desktop, keyboard and reduced motion supported.

## Review Focus
- Refresh after draw but before reveal preserves the exact outcome.
- Importing malformed/inconsistent data cannot overwrite existing history.
- Editing names/queue or settings cannot trigger keyboard spin shortcuts.
- Empty archive, long names, 24 fields and large amounts remain readable.
- A muted or unavailable audio context cannot lock gameplay; voice count is bounded.
